Cómo hacer reportes de problemas en la vista

Módulo Obligatorio
01

¿Qué es un reporte de problema en la vista?

Cuando encontramos algo que no funciona correctamente en la interfaz de la aplicación —un botón que no responde, un texto mal posicionado, datos que no se muestran, o cualquier comportamiento inesperado— debemos documentarlo mediante un reporte de problema.

Un reporte bien redactado permite al equipo de desarrollo reproducir, entender y solucionar el problema de forma eficiente, evitando ir y venir de preguntas.

✓

¿Cuándo reportar?

  • La pantalla no carga o se queda en blanco
  • Un elemento visual está roto o desalineado
  • Un formulario no acepta datos válidos
  • Los datos mostrados no coinciden con los esperados
  • Un flujo de trabajo no puede completarse
✗

¿Cuándo NO es un reporte?

  • No sabes cómo usar una función (→ pide capacitación)
  • Quieres un cambio estético personal (→ solicitud de mejora)
  • El problema ya fue reportado por otro compañero
  • Es un problema de tu conexión o equipo personal
02

Los 6 elementos de un buen reporte

Cada reporte debe contener los siguientes campos. Omitir alguno ralentiza la solución.

1

Título claro y descriptivo

Resume el problema en una sola oración. Incluye la pantalla o sección afectada.

Malo "Algo está mal"
Bueno "Botón 'Guardar' en formulario de Clientes no responde al hacer clic"
2

Pasos para reproducir

Lista numerada, paso a paso, de cómo llegar al problema desde la pantalla inicial.

Ejemplo:

  1. Iniciar sesión con usuario admin@empresa.com
  2. Ir al menú Clientes → Nuevo Cliente
  3. Llenar todos los campos obligatorios
  4. Hacer clic en el botón Guardar
3

Comportamiento esperado vs. comportamiento actual

Describe con precisión qué debería ocurrir y qué ocurre en realidad.

Esperado
El sistema guarda el cliente y muestra el mensaje "Registro creado con éxito".
Actual
No pasa nada al hacer clic. La página no responde y no aparece ningún mensaje.
4

Evidencia visual (captura de pantalla o grabación)

Una imagen vale más que mil palabras. Siempre adjunta una captura o video del problema.

Consejos para capturas efectivas:
  • Captura toda la pantalla, no solo el área del error
  • Si hay un mensaje de error, asegúrate de que sea legible
  • Usa la herramienta de recorte del sistema (Win+Shift+S / Cmd+Shift+4)
  • Para problemas de flujo, considera grabar un video corto con Loom o similares
5

Entorno y datos del sistema

Especifica dónde ocurre el problema para que pueda reproducirse exactamente.

NavegadorChrome 124 / Firefox 125 / Safari 17
Sistema OperativoWindows 11 / macOS Sonoma / Ubuntu 22
URL de la pantallaej: /clientes/nuevo
Usuario afectadoTu correo o rol (admin, vendedor…)
FrecuenciaSiempre / A veces / Solo una vez
Mensaje de errorTexto exacto del error si aparece
6

Prioridad o impacto

Indica qué tan crítico es el problema para el negocio.

Crítico
Bloquea completamente el trabajo. Nadie puede avanzar.
Alto
Afecta funciones principales pero hay solución alternativa.
Medio
Incomoda el trabajo pero no lo bloquea.
Bajo
Problema visual o de detalle menor.
03

Proceso para crear un reporte

🔍

Paso 1 — Verifica que es un bug real

Antes de reportar, descarta causas básicas:

  • Recarga la página (Ctrl+F5 / Cmd+Shift+R)
  • Limpia la caché del navegador
  • Prueba en modo incógnito o en otro navegador
  • Verifica que tu internet funcione correctamente
  • Cierra sesión y vuelve a iniciar
↓
🔎

Paso 2 — Busca si ya fue reportado

Antes de crear un nuevo ticket, revisa el sistema de seguimiento de incidencias (Jira / GitHub Issues / el sistema que use tu equipo) para evitar duplicados. Si ya existe, agrega tus observaciones como comentario.

↓
📝

Paso 3 — Documenta el problema completo

Reúne todos los 6 elementos descritos en la sección anterior antes de abrir el ticket.

↓
🎫

Paso 4 — Crea el ticket en el sistema

Abre un nuevo issue/ticket con toda la información organizada. Usa la plantilla del equipo si existe.

↓
📢

Paso 5 — Notifica al equipo si es urgente

Si el problema es Crítico o Alto, notifica directamente por el canal de comunicación del equipo (Slack, Teams, etc.) con el enlace al ticket. Para problemas Medio o Bajo, el ticket solo es suficiente.

↓
🔄

Paso 6 — Sigue el ticket y responde preguntas

El desarrollador puede necesitar más información. Mantente atento a los comentarios y responde a tiempo. Una vez resuelto, confirma que el problema está corregido antes de cerrar el ticket.

05

Ejemplos: reporte incompleto vs. reporte completo

✗ Reporte incompleto

Título: No funciona

No puedo guardar. El botón no hace nada. Por favor arreglen esto rápido.

Problemas:
  • Título no indica qué pantalla ni qué función
  • No hay pasos para reproducir
  • No se menciona comportamiento esperado
  • Sin captura de pantalla
  • Sin información del entorno
  • Sin prioridad definida
✓ Reporte completo

Título: Botón "Guardar" en Nuevo Cliente no responde al hacer clic

Pasos:

  1. Iniciar sesión como vendedor1@empresa.com
  2. Ir a Clientes → Nuevo Cliente
  3. Llenar todos los campos del formulario
  4. Hacer clic en Guardar

Esperado: El sistema guarda el cliente y muestra "Registro creado".

Actual: Nada ocurre. Sin mensaje, sin redirección.

Entorno: Chrome 124, Windows 11, /clientes/nuevo, rol Vendedor, frecuencia: siempre.

Captura: [imagen adjunta mostrando el formulario lleno y el botón]

Prioridad: 🔴 Crítico — impide registrar nuevos clientes.

¿Por qué es bueno?
  • Título claro con pantalla y acción afectada
  • Pasos específicos y reproducibles
  • Diferencia clara entre esperado y actual
  • Evidencia visual adjunta
  • Entorno completo
  • Prioridad y justificación definidas

07

Resumen y puntos clave

🎯

Sé específico

Describe exactamente qué pantalla, qué acción y qué resultado inesperado obtuviste.

🔁

Hazlo reproducible

Lista los pasos exactos para que cualquiera pueda ver el problema en su equipo.

📸

Muestra evidencia

Una captura o video elimina ambigüedades y acelera la solución.

🌍

Incluye el entorno

Navegador, SO, URL y usuario son datos esenciales para reproducir el error.

⚡

Define la prioridad

Ayudas al equipo a saber cuándo debe atenderse el problema.

🤝

Mantente disponible

Responde las preguntas del desarrollador y confirma la corrección al final.
